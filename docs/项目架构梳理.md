# HazelX 项目架构梳理

本文用于作为项目文档的第一版骨架，重点说明 HazelX 的主要模块、运行链路和各系统之间的关系。

## 1. 项目定位

HazelX 是一个基于 C++17 的实验性游戏/渲染引擎项目，工程结构沿用了 Hazel 引擎的分层风格。当前项目同时包含：

- 引擎核心库：窗口、事件、层系统、渲染抽象、场景 ECS、脚本绑定、基础物理工具。
- 编辑器程序：基于 ImGui 的 Hazelnut，用于加载模型、编辑场景、播放运行时场景。
- C# 脚本运行时：通过 Mono 加载 C# 程序集，并把 C++ 引擎能力暴露给脚本。
- 流体模拟实验：基于 SPH 的 2D 粒子流体模拟代码，目前主要作为 `FluidSimLayer` 实验层存在。

README 中的项目描述是“基于 SPH 的流体模拟”，但从源码来看，当前仓库已经扩展成了一个带编辑器、PBR 渲染和 Mono 脚本系统的综合引擎实验项目。

## 2. 工程结构

顶层目录职责如下：

| 目录/文件 | 作用 |
| --- | --- |
| `HazelX/` | C++ 引擎核心静态库，包含 Core、Renderer、Scene、Script、Physics2D、Platform 等模块 |
| `Hazelnut/` | 编辑器/工具端程序，入口是 `Hazelnut.cpp`，主要逻辑在 `EditorLayer` |
| `Hazel-ScriptCore/` | C# 脚本基础库，定义 `Entity`、`Component`、数学类型、输入、渲染资源封装 |
| `ExampleApp/` | C# 脚本示例程序集，例如 `BasicController`、`MapGenerator` |
| `assets/` | 运行时资源目录，包含脚本 DLL、场景、模型、纹理、shader 等 |
| `Hazelnut/assets/` | 编辑器示例资源和 shader |
| `vendor/`、`HazelX/vendor/` | 第三方依赖，包括 GLFW、Glad、ImGui、GLM、entt、Assimp、Mono、yaml-cpp、stb、spdlog |
| `premake5.lua` | Premake 工程生成脚本，定义 HazelX、Hazelnut、Hazel-ScriptCore 等项目 |

Premake 中的主项目关系：

- `HazelX`：静态库，C++17，引擎核心。
- `Hazel-ScriptCore`：C# SharedLib，生成脚本基础 DLL。
- `Hazelnut`：C++ ConsoleApp，链接 `HazelX`，作为默认启动项目。

## 3. 整体运行链路

程序入口由引擎提供，应用端只需要实现 `Hazel::CreateApplication()`。

1. `Hazel/EntryPoint.h` 定义 Windows 下的 `main()`。
2. `main()` 初始化日志，调用 `CreateApplication()` 创建应用。
3. `Hazelnut.cpp` 创建 `HazelnutApplication`，窗口大小为 `1600x900`。
4. `Application` 构造阶段创建窗口、ImGui Layer、初始化脚本引擎和渲染器。
5. `Application::Run()` 进入主循环：
   - 更新所有 Layer。
   - 提交 ImGui 渲染命令。
   - 执行 `Renderer::WaitAndRender()` 消费渲染命令队列。
   - 更新窗口和帧时间。

核心运行循环可以概括为：

```text
EntryPoint main
  -> CreateApplication
  -> Application::Run
      -> Layer::OnUpdate
      -> Renderer::Submit(ImGui)
      -> Renderer::WaitAndRender
      -> Window::OnUpdate
```

## 4. 核心架构模块

### 4.1 Core

位置：`HazelX/src/Hazel/Core`

Core 模块负责引擎基础能力：

- `Application`：应用生命周期、窗口持有、LayerStack、事件分发、ImGui 渲染入口。
- `Window`：平台窗口抽象，实际实现位于 `Platform/Windows/WindowsWindow.*`。
- `Layer` / `LayerStack`：应用功能层系统，编辑器层和 ImGui 层都通过它挂载。
- `Event` 系列：窗口、键盘、鼠标事件定义和分发。
- `Input`：输入抽象，Windows 实现在 `Platform/Windows/WindowsInput.cpp`。
- `Log`：spdlog 封装。
- `UUID`：场景和实体 ID。
- `Timestep` / `Timer`：时间步和计时工具。

### 4.2 Platform

位置：`HazelX/src/Platform`

当前主要后端：

- `Windows`：窗口、输入。
- `OpenGL`：RendererAPI、Buffer、VertexArray、Shader、Texture、Framebuffer、RenderPass 的 OpenGL 实现。

渲染接口本身在 `Hazel/Renderer` 下定义，平台目录负责具体实现。这让上层系统可以通过统一接口使用图形资源。

## 5. 场景与 ECS 系统

位置：`HazelX/src/Hazel/Scene`

场景系统基于 entt：

- `Scene` 持有 `entt::registry`，管理实体和组件。
- `Entity` 是对 `entt::entity + Scene*` 的轻量封装。
- `Components.h` 定义组件类型。
- `SceneSerializer` 使用 yaml-cpp 进行场景序列化和反序列化。

当前主要组件：

| 组件 | 作用 |
| --- | --- |
| `IDComponent` | 保存实体 UUID |
| `TagComponent` | 实体名称 |
| `TransformComponent` | 实体变换矩阵 |
| `MeshComponent` | 3D 网格资源 |
| `ScriptComponent` | C# 脚本模块名 |
| `CameraComponent` | 场景相机 |
| `SpriteRendererComponent` | 2D 精灵渲染数据 |

场景有两种主要渲染入口：

- `OnRenderEditor(ts, editorCamera)`：编辑器模式，使用 `EditorCamera`，支持选中物体描边。
- `OnRenderRuntime(ts)`：运行时模式，查找 Primary Camera，并使用实体相机渲染。

运行时播放时，编辑器会复制一份场景：

```text
Editor Scene
  -> CopyTo(Runtime Scene)
  -> Runtime Scene OnRuntimeStart
  -> 脚本实例化
```

这样运行时修改不会直接污染编辑器场景。

## 6. 渲染系统

位置：`HazelX/src/Hazel/Renderer`、`HazelX/src/Platform/OpenGL`

渲染系统分为三层：

1. 高层场景渲染：`SceneRenderer`
2. 通用渲染提交：`Renderer`
3. 平台图形 API：`RendererAPI` 和 OpenGL 后端

### 6.1 Renderer 命令队列

`Renderer` 维护 `RenderCommandQueue`。上层调用 `Renderer::Submit()` 把 lambda 写入队列，最后由 `Renderer::WaitAndRender()` 统一执行。

这样做的设计意图是把渲染命令提交和实际执行解耦，为后续渲染线程或命令缓冲扩展留接口。

典型流程：

```text
Layer/Scene 提交渲染任务
  -> Renderer::Submit(lambda)
  -> RenderCommandQueue::Allocate
  -> Application 主循环中 Renderer::WaitAndRender
  -> 依次执行 OpenGL 调用
```

### 6.2 SceneRenderer

`SceneRenderer` 是 3D 场景渲染主流程，内部维护：

- `GeoPass`：HDR/MSAA 几何渲染 Pass，默认 `RGBA16F`。
- `CompositePass`：最终合成 Pass，默认 `RGBA8`。
- `DrawList`：普通 Mesh 绘制队列。
- `SelectedMeshDrawList`：编辑器选中对象队列。
- `GridMaterial`：编辑器网格。
- `OutlineMaterial`：选中物体描边。
- `BRDFLUT`、环境贴图资源。

渲染流程：

```text
SceneRenderer::BeginScene
  -> Scene 提交 Mesh 到 DrawList
SceneRenderer::EndScene
  -> FlushDrawList
      -> GeometryPass
          -> Skybox
          -> Mesh PBR
          -> Selected Outline
          -> Grid / AABB Debug
      -> CompositePass
          -> HDR/MSAA 结果合成到最终 framebuffer
```

### 6.3 PBR 与环境贴图

项目包含 PBR shader 和 IBL 预处理 shader：

- `HazelPBR_Static.glsl`
- `HazelPBR_Anim.glsl`
- `Skybox.glsl`
- `EquirectangularToCubeMap.glsl`
- `EnvironmentMipFilter.glsl`
- `EnvironmentIrradiance.glsl`
- `SceneComposite.glsl`

`SceneRenderer::CreateEnvironmentMap()` 会把 HDR equirectangular 贴图转换成立方体贴图，并生成：

- Radiance Map：用于镜面环境反射。
- Irradiance Map：用于漫反射环境光。

### 6.4 Mesh 与材质

`Mesh` 使用 Assimp 加载模型，支持：

- 静态网格。
- 骨骼动画网格。
- Submesh。
- AABB。
- 材质和纹理读取。
- 三角形缓存，用于编辑器选择/拾取等功能。

材质系统分为：

- `Material`：材质模板，持有 shader、默认 uniform、默认 texture。
- `MaterialInstance`：材质实例，允许覆盖模板参数。

这种设计可以复用同一个 shader/材质模板，同时给不同网格或 submesh 设置不同参数。

### 6.5 Renderer2D

`Renderer2D` 提供 2D Quad、Line 等绘制能力。当前用途包括：

- 调试 AABB 线框。
- 流体模拟中的粒子和容器绘制。
- 未来 2D 精灵渲染。

## 7. 编辑器系统

位置：`Hazelnut/src`、`HazelX/src/Hazel/Editor`

编辑器程序名为 Hazelnut，主 Layer 是 `EditorLayer`。

主要功能：

- ImGui DockSpace 布局。
- 视口窗口显示 `SceneRenderer` 最终 framebuffer。
- 环境贴图加载。
- 光照、曝光、Skybox LOD 等参数编辑。
- 场景层级面板。
- 实体属性面板。
- 组件添加。
- ImGuizmo 变换编辑。
- 编辑/播放状态切换。
- 场景保存和加载。
- 鼠标射线拾取与实体选择。

编辑器状态：

| 状态 | 说明 |
| --- | --- |
| `Edit` | 编辑器相机渲染编辑场景 |
| `Play` | 复制编辑场景为运行时场景，执行脚本和运行时渲染 |
| `Pause` | 保留运行时场景但暂停更新 |

## 8. 脚本系统

位置：

- C++：`HazelX/src/Hazel/Script`
- C#：`Hazel-ScriptCore/src/Hazel`
- 示例：`ExampleApp/src`

脚本系统基于 Mono。引擎启动时：

1. `Application` 调用 `ScriptEngine::Init("assets/scripts/ExampleApp.dll")`。
2. `ScriptEngine` 初始化 Mono Domain。
3. 加载 `assets/scripts/Hazel-ScriptCore.dll`。
4. 加载应用脚本 DLL，例如 `ExampleApp.dll`。
5. 注册 C++ internal call。

### 8.1 C# 脚本模型

C# 侧脚本继承 `Hazel.Entity`。例如：

```csharp
namespace Example
{
    public class BasicController : Entity
    {
        public float Speed;

        public void OnUpdate(float ts)
        {
            Matrix4 transform = GetTransform();
            Vector3 translation = transform.Translation;
            // 根据输入修改 translation
            transform.Translation = translation;
            SetTransform(transform);
        }
    }
}
```

实体通过 `ScriptComponent.ModuleName` 指定脚本类名，例如 `Example.BasicController`。

### 8.2 脚本生命周期

```text
实体添加 ScriptComponent
  -> OnScriptComponentConstruct
  -> ScriptEngine::InitScriptEntity
      -> 查找 MonoClass
      -> 查找 OnCreate / OnUpdate
      -> 扫描 public fields

场景播放
  -> Scene::OnRuntimeStart
  -> InstantiateEntityClass
      -> 创建 C# 对象
      -> 注入实体 UUID 到 C# Entity.ID
      -> 写入序列化保存的 public fields
      -> 调用 OnCreate

每帧更新
  -> Scene::OnUpdate
  -> ScriptEngine::OnUpdateEntity
  -> 调用 C# OnUpdate(float ts)
```

### 8.3 C++ 与 C# 绑定

`ScriptEngineRegistry::RegisterAll()` 使用 `mono_add_internal_call` 注册 C++ 函数给 C#：

- 输入：`Input.IsKeyPressed`
- 噪声：`Noise.PerlinNoise`
- 实体：获取/设置 Transform，创建/判断组件
- MeshComponent：获取/设置 Mesh
- Texture2D：创建、销毁、写入数据
- Material / MaterialInstance：设置 float、vector、texture
- Mesh：加载、获取材质
- MeshFactory：创建 Plane

脚本 public 字段会被反射出来，支持保存和恢复：

- `float`
- `int`
- `uint`
- `Vector2`
- `Vector3`
- `Vector4`

`string` 类型目前识别了枚举，但序列化/字段缓冲还未完整实现。

## 9. 物理系统与 SPH 流体模拟

位置：

- 基础物理：`HazelX/src/Hazel/Physics2D`
- 流体实验层：`Hazelnut/src/FluidSimLayer.*`

### 9.1 Physics2D

`Physics2D` 目前不是完整刚体物理引擎，而是为 2D 粒子模拟提供的一组静态工具函数：

- AABB 点检测。
- 粒子与矩形边界碰撞。
- 粒子与圆形障碍物碰撞。
- SPH 平滑核函数。
- 平滑核梯度。
- 密度计算。
- 属性插值。
- 梯度计算。

核心粒子结构：

```cpp
struct Particle2D
{
    glm::vec2 Position;
    glm::vec2 Velocity;
    float Density;
    float Property;
};
```

### 9.2 SPH 流体模拟

`FluidSimLayer` 设计为一个独立 Layer，使用 2D 正交相机和 framebuffer 绘制流体模拟。它包含：

- 粒子数量、半径、重力、碰撞阻尼。
- SPH 参数：平滑半径、目标密度、压力系数、粘性系数。
- 模拟边界：盒子宽高。
- 圆形障碍物。
- 鼠标交互力。
- 空间哈希加速结构。

每帧模拟流程：

```text
BuildSpatialHash
  -> 计算每个粒子密度
  -> 根据密度计算压力
  -> 遍历邻域计算压力力和粘性力
  -> 加入重力和鼠标交互力
  -> 更新速度
  -> 更新位置
  -> 处理边界和圆形障碍物碰撞
  -> Renderer2D 绘制容器、障碍物、粒子
```

需要注意：当前 `FluidSimLayer.cpp` 中实现代码整体处于注释状态，因此它更像是保留的实验代码或待恢复模块。`Hazelnut.cpp` 当前挂载的是 `EditorLayer`，不是 `FluidSimLayer`。

## 10. 资产与序列化

### 10.1 场景序列化

`SceneSerializer` 使用 YAML 保存：

- Scene 名称。
- Environment：HDR 路径、灯光方向、颜色、强度。
- Entities：
  - UUID
  - Tag
  - Transform
  - ScriptComponent 和 public fields
  - MeshComponent 的 AssetPath
  - CameraComponent
  - SpriteRendererComponent

保存和加载入口在编辑器菜单中，通过 `Application::OpenFile()` / `SaveFile()` 调用 Windows 文件对话框。

### 10.2 模型与贴图

模型加载由 Assimp 处理，支持常见格式如 FBX、DAE、OBJ。材质读取时会尝试加载：

- Albedo / Diffuse
- Normal
- Roughness
- Metalness

贴图路径目前主要基于模型文件的父目录拼接，相当于局部资源路径方案，尚未形成完整 Asset Manager。

## 11. 当前系统关系图

```text
Hazelnut Editor
  -> HazelX Application / LayerStack
      -> Window + Events + Input
      -> ImGuiLayer
      -> EditorLayer
          -> SceneHierarchyPanel
          -> EditorCamera
          -> Scene
              -> entt Registry
              -> Components
              -> SceneSerializer
              -> ScriptEngine
              -> SceneRenderer
                  -> Renderer
                      -> RenderCommandQueue
                      -> RendererAPI
                          -> OpenGL backend
```

脚本侧关系：

```text
ExampleApp.dll
  -> Hazel-ScriptCore.dll
      -> internal call
          -> ScriptWrappers.cpp
              -> Scene / Entity / Renderer / Input / Mesh / Material
```

SPH 流体关系：

```text
FluidSimLayer
  -> Physics2D SPH helper
  -> Spatial Hash
  -> Renderer2D
  -> Framebuffer
  -> ImGui Viewport
```

## 13. 当前实现状态与注意点

- `FluidSimLayer.cpp` 当前整文件被注释，正式文档中应说明它是实验/待启用模块。
- `Physics2D` 是 SPH 辅助工具，不是完整 2D 刚体系统。
- `Renderer` 已经有命令队列抽象，但当前仍在主循环内同步执行。
- `SceneRenderer` 已有多 Pass 结构，但还不是完整渲染管线/Render Graph。
- `ScriptEngine` 支持 public 字段反射和序列化，但 `string` 字段尚未完整实现。
- `SceneSerializer` 中 Camera 数据目前保存较简略，`SerializeRuntime` / `DeserializeRuntime` 未实现。
- 资源路径仍比较直接，没有统一 Asset Handle 或 Asset Database。
- 项目代码中存在一些 TODO 和临时实现，正式文档可以把这些归入“限制与未来工作”。
