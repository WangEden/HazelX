## 1. Bug 修复：程序退出时 xhash.h 触发中断

### 1.1 问题根因

程序退出流程为：

```
main()
  -> app->Run()       // 主循环结束，调用 OnShutdown()
  -> delete app       // 调用 ~Application()
```

**`Application::~Application()` 是空的**（见 `Application.cpp:43-45`）。这导致以下问题：

1. **ImGuiLayer::OnDetach() 从未被调用**。ImGui 的 OpenGL backend 和 GLFW backend 都没有执行 Shutdown，ImGui Context 也没有被销毁。当 `delete app` 触发 `m_Window`（`unique_ptr<Window>`）析构时，GLFW 窗口被销毁，但 ImGui 还持有已失效的 OpenGL context 指针。

2. **ScriptEngine::Shutdown() 没有调用 ShutdownMono()**。`ScriptEngine.cpp:281-286` 中 Shutdown 只清了 map，但没有调用 `mono_jit_cleanup`（`ShutdownMono()` 函数在第 116-119 行已经定义了，只是没被调用）。Mono 运行时持有大量内部资源，在静态析构阶段尝试清理时会访问已无效的内存。

3. **Renderer 没有执行 Shutdown**。`RenderCommandQueue` 中可能还有未执行的命令，OpenGL 资源（VAO、VBO、Shader、Framebuffer）也没有被释放。

**xhash.h 触发中断的直接原因**：当程序退出时，C++ 运行时开始销毁静态/全局对象。此时 Mono runtime 和 ImGui context 处于半死不活的状态，它们内部的 `std::unordered_map`（依赖 `std::hash`，实现在 xhash.h 中）试图析构或 rehash，但底层内存已被破坏，触发 VS 的调试中断。

### 1.2 修复方案

在 `Application::~Application()` 中按正确顺序清理所有资源：

```cpp
// Application.cpp — 修改 Application::~Application()
Application::~Application()
{
    // 1. 先关闭脚本引擎（释放 Mono 运行时）
    ScriptEngine::Shutdown();  // 这里需要修改 ScriptEngine::Shutdown() 的实现

    // 2. 清理所有 Layer（包括 EditorLayer 等）
    // 注意：ImGuiLayer 是 overlay，在 LayerStack 末尾
    // 需要先清理非 ImGui 的 layer，最后处理 ImGuiLayer
    while (!m_LayerStack.empty())
    {
        Layer* layer = m_LayerStack.back();
        m_LayerStack.PopOverlay(layer);  // 或 PopLayer
        layer->OnDetach();
        delete layer;
    }

    // ImGuiLayer 已经在上面被清理了，将指针置空
    m_ImGuiLayer = nullptr;

    // 3. 关闭渲染器（释放 OpenGL 资源）
    Renderer::Shutdown();

    // 4. 窗口会由 unique_ptr 自动销毁，但此时所有依赖它的资源都已释放
}
```

同时修改 `ScriptEngine::Shutdown()`：

```cpp
// ScriptEngine.cpp — 修改 ScriptEngine::Shutdown()
void ScriptEngine::Shutdown()
{
    s_SceneContext = nullptr;
    s_EntityInstanceMap.clear();
    s_EntityClassMap.clear();

    // 关键：实际关闭 Mono 运行时
    ShutdownMono();
}
```

**清理顺序原则**：先关最高层依赖（脚本），再关中间层（ImGui/Layers），最后关底层（渲染器、窗口）。

### 1.3 涉及文件

| 文件 | 改动 |
|------|------|
| `HazelX/src/Hazel/Core/Application.cpp` | 实现析构函数，添加完整清理逻辑 |
| `HazelX/src/Hazel/Script/ScriptEngine.cpp` | `Shutdown()` 中添加 `ShutdownMono()` 调用 |
| `HazelX/src/Hazel/Renderer/Renderer.h/cpp` | 添加 `Renderer::Shutdown()` 函数 |
| `HazelX/src/Hazel/Core/LayerStack.h/cpp` | 确认有 `PopOverlay`/`PopLayer` 方法，确认 `empty()` 可用 |

### 1.4 Renderer::Shutdown 的实现参考

```cpp

// Renderer.cpp 中实现

{
```

## 2. ImGui 深色主题实现

### 2.1 当前状态

你的 `ImGuiLayer::OnAttach()`（`ImGuiLayer.cpp:48`）使用的是 `ImGui::StyleColorsDark()`，这是 ImGui 内置的默认深色主题，颜色偏蓝灰色。

Hazel-dev 有两套自定义主题：
- `SetDarkThemeColors()`：基础自定义深色主题
- `SetDarkThemeV2Colors()`：更完善的深色主题，使用 `Colors::Theme` 命名空间中定义的颜色常量

### 2.3 为什么只改颜色还不够

颜色只是冰山一角。Hazel-dev 的编辑器看起来"高级"，核心原因是三个层面的改变：

| 层面 | 你的项目 | Hazel-dev |
|------|---------|-----------|
| **标题栏** | ImGui 默认标题栏（蓝色/灰色，带关闭按钮） | 完全自定义：黑色，57px 高，内嵌 Logo + 菜单栏 + 窗口控件 |
| **DockSpace** | 普通窗口内创建 DockSpace | 窗口铺满整个屏幕，`NoTitleBar`，标题栏手动绘制 |
| **字体** | LXGW WenKai 18px 单一字体 | Roboto 多字号族（10/12/15/18/24px）+ FontAwesome 图标 |
| **窗口圆角** | ImGui 默认圆角 | `WindowRounding = 0.0f`，完全方正 |
| **面板间距** | 默认间距 | `WindowPadding` 精确控制，非最大化时 `WindowBorderSize = 3.0f` |

下面的 2.4-2.7 是按优先级排列的改进步骤，可以逐步实施。

### 2.4 步骤 A：完善 Style 参数（快速，只改 ImGuiLayer）

在 `SetDarkThemeV2Colors()` 中补充以下 style 设置：

### 2.5 步骤 B：替换字体（中等工作量）

Hazel-dev 使用 Roboto 字体族。建议替换你的 LXGW WenKai 为更现代的无衬线字体。

**方案一：直接用 Roboto（与 Hazel-dev 一致）**

下载 Roboto 字体（Google Fonts 免费提供），放入 `assets/fonts/`：

```
assets/fonts/
├── Roboto-Regular.ttf
├── Roboto-Bold.ttf
└── Roboto-Medium.ttf
```

在 `ImGuiLayer::OnAttach()` 中加载多个字号：

```cpp
ImFont* fontDefault = io.Fonts->AddFontFromFileTTF("assets/fonts/Roboto-Regular.ttf", 15.0f);
ImFont* fontBold    = io.Fonts->AddFontFromFileTTF("assets/fonts/Roboto-Bold.ttf", 18.0f);
ImFont* fontLarge   = io.Fonts->AddFontFromFileTTF("assets/fonts/Roboto-Regular.ttf", 24.0f);
ImFont* fontSmall   = io.Fonts->AddFontFromFileTTF("assets/fonts/Roboto-Regular.ttf", 12.0f);
io.FontDefault = fontDefault;
```

**方案二：继续用 LXGW WenKai 但调小字号**

如果喜欢当前字体，建议把 18px 降到 15-16px，间距会更紧凑：

```cpp

```

### 2.6 步骤 C：自定义标题栏（工作量最大，但效果最显著）

这是 Hazel-dev 编辑器看起来"没有丑陋标题栏"的真正原因。

**原理**：

1. DockSpace 所在的 ImGui 窗口完全铺满屏幕，使用 `NoTitleBar` 禁掉默认标题栏
2. 在窗口内部用 `ImGui::GetWindowDrawList()->AddRectFilled()` 手动画一个矩形作为标题栏
3. 在标题栏上用 ImGui 控件绘制：Logo、菜单项、窗口操作按钮

**在你的 EditorLayer::OnImGuiRender() 中实现**：

```cpp
void EditorLayer::OnImGuiRender()
{
    // === 1. 创建铺满屏幕的 DockSpace 窗口 ===
    ImGuiWindowFlags window_flags = ImGuiWindowFlags_NoDocking;
    ImGuiViewport* viewport = ImGui::GetMainViewport();
    ImGui::SetNextWindowPos(viewport->Pos);
    ImGui::SetNextWindowSize(viewport->Size);
    ImGui::SetNextWindowViewport(viewport->ID);

    // 关键：去掉默认标题栏
    window_flags |= ImGuiWindowFlags_NoTitleBar
                  | ImGuiWindowFlags_NoCollapse
                  | ImGuiWindowFlags_NoResize
                  | ImGuiWindowFlags_NoMove
                  | ImGuiWindowFlags_NoBringToFrontOnFocus
                  | ImGuiWindowFlags_NoNavFocus;

    ImGui::PushStyleVar(ImGuiStyleVar_WindowRounding, 0.0f);
    ImGui::PushStyleVar(ImGuiStyleVar_WindowBorderSize, 0.0f);
    ImGui::PushStyleVar(ImGuiStyleVar_WindowPadding, ImVec2(0.0f, 0.0f));

    ImGui::Begin("DockSpace", nullptr, window_flags);
    ImGui::PopStyleVar(3);

    // === 2. 绘制自定义标题栏 ===
    float titlebarHeight = 30.0f;  // 标题栏高度

    // 用 DrawList 绘制标题栏背景
    ImVec2 titlebarMin = ImGui::GetCursorScreenPos();
    ImVec2 titlebarMax = ImVec2(
        titlebarMin.x + ImGui::GetWindowWidth(),
        titlebarMin.y + titlebarHeight
    );
    ImGui::GetWindowDrawList()->AddRectFilled(
        titlebarMin, titlebarMax,
        IM_COL32(21, 21, 21, 255)  // Colors::Theme::titlebar
    );

    // === 3. 在标题栏上绘制内容 ===
    ImGui::SetCursorPos(ImVec2(10.0f, 3.0f));
    ImGui::TextUnformatted("HazelX Editor");  // 编辑器名称

    // 菜单栏（紧跟在标题文字后面）
    ImGui::SameLine(120.0f);
    if (ImGui::BeginMenuBar())
    {
        if (ImGui::BeginMenu("File"))
        {
            if (ImGui::MenuItem("New Scene", "Ctrl+N")) { /* 新建场景 */ }
            if (ImGui::MenuItem("Open Scene...", "Ctrl+O")) { /* 打开场景 */ }
            if (ImGui::MenuItem("Save Scene", "Ctrl+S")) { /* 保存场景 */ }
            ImGui::Separator();
            if (ImGui::MenuItem("Exit")) { /* 退出 */ }
            ImGui::EndMenu();
        }
        // ... Edit, View 等菜单
        ImGui::EndMenuBar();
    }

    // 窗口操作按钮（右上角）
    float buttonY = 3.0f;
    float buttonWidth = 30.0f;
    float windowWidth = ImGui::GetWindowWidth();

    ImGui::SetCursorPos(ImVec2(windowWidth - buttonWidth * 3, buttonY));
    if (ImGui::Button(" - ", ImVec2(buttonWidth, titlebarHeight - 6))) { /* 最小化 */ }
    ImGui::SetCursorPos(ImVec2(windowWidth - buttonWidth * 2, buttonY));
    if (ImGui::Button(" □ ", ImVec2(buttonWidth, titlebarHeight - 6))) { /* 最大化/还原 */ }
    ImGui::SetCursorPos(ImVec2(windowWidth - buttonWidth, buttonY));
    ImGui::PushStyleColor(ImGuiCol_Button, ImVec4(0.8f, 0.1f, 0.1f, 1.0f));
    ImGui::PushStyleColor(ImGuiCol_ButtonHovered, ImVec4(1.0f, 0.2f, 0.2f, 1.0f));
    if (ImGui::Button(" X ", ImVec2(buttonWidth, titlebarHeight - 6)))
    {
        // 关闭窗口
        auto& app = Hazel::Application::Get();
        Hazel::WindowCloseEvent e;
        app.OnEvent(e);
    }
    ImGui::PopStyleColor(2);

    // === 4. 标题栏下方开始 DockSpace ===
    ImGui::SetCursorPosY(titlebarHeight);
    ImGuiID dockspaceId = ImGui::GetID("MyDockspace");
    ImGui::DockSpace(dockspaceId, ImVec2(0.0f, 0.0f));

    // === 5. 正常的编辑器面板 ===
    // Viewport, SceneHierarchyPanel, PropertiesPanel 等

    ImGui::End(); // DockSpace 窗口
}
```

**注意**：这是一个简化版实现。Hazel-dev 的标题栏更复杂，包含渐变色、Logo 纹理、动画效果、窗口拖拽等。你可以先从上面的简化版开始，再逐步完善。

### 2.7 步骤 D：窗口拖拽和标题栏交互

如果想让自定义标题栏支持拖拽窗口，需要：

```cpp
// 检测标题栏区域的鼠标拖拽
if (ImGui::IsMouseHoveringRect(titlebarMin, titlebarMax)
    && ImGui::IsMouseClicked(ImGuiMouseButton_Left))
{
    // 调用 GLFW 的窗口拖拽
    // Windows: SendMessage(hwnd, WM_NCLBUTTONDOWN, HTCAPTION, 0)
    // 或者使用 glfwSetWindowPos 手动跟踪
}
```

更完整的做法是处理 Windows 的 `WM_NCHITTEST` 消息，让系统认为标题栏区域是窗口标题栏，这样系统自动处理拖拽、双击最大化等行为。这需要在 `WindowsWindow.cpp` 的窗口过程回调中处理。

### 3.3 Hazel-dev 的关键架构设计

#### 3.3.1 渲染线程

Hazel-dev 使用独立的 `RenderThread` 类，将渲染完全从主线程分离：

```
Main Thread                    Render Thread
    │                              │
    │  Layer::OnUpdate()           │
    │  ─────────────────>  Renderer::Submit(cmd)
    │                       命令入队
    │                              │
    │  BlockUntilRenderComplete()  │
    │  <───────────────────        │
    │                              │
    │  Kick() 开始下一帧渲染 ──>   │ Execute()
    │                              │
```

`FramesInFlight` 机制：默认 2 帧在飞，主线程和渲染线程交替操作不同的命令队列，避免竞争。

#### 3.3.2 资产系统

Hazel-dev 的 `AssetManager` 提供：
- **Asset Handle**：每个资产有唯一 ID
- **异步加载**：后台线程加载资产
- **热重载**：检测文件变化，自动重新编译/加载
- **依赖追踪**：追踪资产间的引用关系
- **内存资产**：运行时创建的资产

资产类型覆盖：Mesh、Texture、Material、Shader、Audio、Prefab、Scene、AnimationGraph 等。

#### 3.3.3 脚本系统 (Coral)

Hazel-dev 从 Mono 直接绑定迁移到了 Coral（一个 .NET 互操作库）：
- 目标 .NET 8
- 更好的类型安全
- 脚本热重载支持
- Editor 属性系统（在 C# 中标注 `[EditorVisible]` 等）
- 字段序列化更完善

#### 3.3.4 入口点设计

```cpp
// Hazel-dev EntryPoint.h
bool g_ApplicationRunning = true;

int Main(int argc, char** argv)
{
    while (g_ApplicationRunning)
    {
        InitializeCore();
        Application* app = CreateApplication(argc, argv);
        app->Run();
        delete app;
        ShutdownCore();
    }
    return 0;
}
```

注意外层 `while (g_ApplicationRunning)` 循环——支持编辑器在关闭后重新启动应用（热重载场景）。

#### 3.3.5 Application 析构流程

```cpp
Application::~Application()
{
    ScriptEngine::GetMutable().ShutdownHost();
    NFD::Quit();
    EditorApplicationSettingsSerializer::SaveSettings();
    m_Window->SetEventCallback([](Event& e) {});  // 清空回调，防止野指针
    m_RenderThread.Terminate();
    for (Layer* layer : m_LayerStack) {
        layer->OnDetach();
        delete layer;
    }
    Project::SetActive(nullptr);
    Font::Shutdown();
    MiniAudioEngine::Shutdown();
    Renderer::Shutdown();
    delete m_Profiler;
}
```

关键细节：
- 清空 Window 事件回调（`[]Event& e) {}`），防止析构过程中收到事件
- 先终止渲染线程，再清理 layers
- 最后关闭 Renderer

## 5. 分模块架构演进路线

以下是建议的改进顺序，从最紧迫到长期目标。每个阶段相对独立，可以单独完成并验证。

### Phase 0：修复关键 Bug（优先级：立即）

> 这是前置步骤，不涉及架构变更。

- [ ] 实现 `Application::~Application()` 的完整清理逻辑
- [ ] 修复 `ScriptEngine::Shutdown()`，调用 `ShutdownMono()`
- [ ] 添加 `Renderer::Shutdown()`
- [ ] 验证：程序可以正常退出，不再触发 xhash.h 中断

### Phase 1：基础健壮性（优先级：高）

> 目标：让引擎更稳定，减少崩溃。

#### 1.1 LayerStack 生命周期管理

**问题**：当前 `PushLayer`/`PushOverlay` 负责 OnAttach，但析构时没有统一的 OnDetach + delete 流程。

**Hazel-dev 做法**：析构函数遍历 LayerStack，逐个 OnDetach + delete。同时有 PopLayer/PopOverlay 方法。

**建议改动**：

- `LayerStack` 添加 `PopLayer(Layer*)` 和 `PopOverlay(Layer*)` 方法（调用 OnDetach）
- `LayerStack` 添加 `empty()` 查询和迭代支持
- `Application` 析构中使用统一的 layer 清理逻辑

**涉及文件**：`LayerStack.h/cpp`, `Application.cpp`

#### 1.2 ApplicationSpecification

**问题**：当前使用 `ApplicationProps` 结构体，参数少且不支持运行时配置。

**Hazel-dev 做法**：使用 `ApplicationSpecification`，包含窗口大小、VSync、全屏、工作目录、是否启用 ImGui、渲染配置、线程策略等。

**建议改动**：

```cpp
struct ApplicationSpecification
{
    std::string Name = "Hazel Engine";
    uint32_t WindowWidth = 1920, WindowHeight = 1080;
    bool WindowDecorated = true;
    bool Fullscreen = false;
    bool VSync = true;
    bool StartMaximized = false;
    bool Resizable = true;
    bool EnableImGui = true;
    std::string WorkingDirectory;
};
```

**涉及文件**：`Application.h`, `Application.cpp`

#### 1.3 ImGui 主题系统

**问题**：使用默认 StyleColorsDark，视觉上不够专业。

**建议改动**：按第 2 节的方案实现 Colors.h + SetDarkThemeV2Colors。

**涉及文件**：`ImGuiLayer.h/cpp`, 新建 `Colors.h`

#### 1.4 帧时间安全限制

**问题**：`m_TimeStep = time - m_LastFrameTime` 没有上限。如果窗口被拖动或调试中断，恢复后可能产生巨大的 timestep。

**Hazel-dev 做法**：`m_TimeStep = glm::min<float>(frametime, 0.0333f);`

**建议改动**：

```cpp
float time = GetTime();
m_TimeStep = glm::min<float>(time - m_LastFrameTime, 0.0333f);
m_LastFrameTime = time;
```

**涉及文件**：`Application.cpp` Run() 方法

### Phase 2：事件系统增强（优先级：中高）

> 目标：更灵活的事件处理，支持异步事件和跨线程事件派发。

#### 2.1 WindowMinimize 事件

**Hazel-dev** 有独立的 `WindowMinimizeEvent`，用于精确控制 `m_Minimized` 状态。当前 HazelX 只在 Resize 中判断 width/height == 0。

**涉及文件**：事件定义文件，`Application.cpp`

#### 2.2 事件队列

**Hazel-dev** 的 Application 有 `m_EventQueue`（`std::deque<std::pair<bool, std::function<void()>>>`），支持延迟处理事件。

这为渲染线程和主线程的协作提供了基础：渲染线程可以往队列里投递事件，主线程在适当时机（帧同步点）处理。

**当前不急**，但如果后续要做渲染线程，这是前置依赖。

### Phase 3：渲染系统升级（优先级：中）

> 目标：让渲染系统更灵活、可扩展。

#### 3.1 Renderer::Shutdown 和资源释放

**当前状态**：没有统一的 Renderer 关闭流程。

**建议改动**：
- `Renderer::Shutdown()` 清理所有静态资源（ShaderLibrary、FullscreenQuadVAO 等）
- `Renderer2D::Shutdown()` 清理 2D 渲染资源
- `RendererAPI::Shutdown()` 清理 OpenGL 状态

**涉及文件**：`Renderer.h/cpp`, `Renderer2D.h/cpp`, `RendererAPI.h/cpp`

#### 3.2 RenderCommandQueue 改进

**当前状态**：单队列、单线程执行。

**短期改进**：
- 添加队列清空/重置方法
- 确保 Shutdown 时队列中没有未执行的命令

**长期（渲染线程）**：
- 双缓冲 CommandQueue（主线程写 A，渲染线程执行 B，每帧交换）
- `FramesInFlight` 概念

**涉及文件**：`RenderCommandQueue.h/cpp`, `Renderer.h/cpp`

#### 3.3 场景灯光扩展

**当前状态**：只有方向光。

**建议增加**：
- `PointLightComponent`
- `SpotLightComponent`
- 多灯光渲染支持

**涉及文件**：`Components.h`, `SceneRenderer.cpp`, PBR shader

### Phase 4：资产管理基础（优先级：中）

> 目标：从直接文件路径迁移到基于 Handle 的资产管理。

### Phase 5：脚本系统改进（优先级：中低）

> 注意：Hazel-dev 已经从 Mono 迁移到了 Coral，但这个迁移工作量巨大。建议先完善现有 Mono 集成。

#### 5.1 完善 ScriptEngine::Shutdown

确保 Shutdown 时释放所有 Mono 资源：GC handles、assemblies、domains。

#### 5.2 字段类型扩展

- 卸载旧 domain 前释放所有 GC handles
- 重新加载后正确恢复脚本实例和字段值

### Phase 6：编辑器增强（优先级：低）

### Phase 7：长期目标（优先级：探索）

这些是大规模改动，需要大量时间和规划：

#### 7.1 渲染线程

基于 `RenderThread` 类实现主线程/渲染线程分离。这是性能提升的关键，但涉及整个渲染管线的重构。

前置依赖：
- Phase 2（事件队列）
- Phase 3（双缓冲 CommandQueue）

#### 7.2 Vulkan 后端

如果目标是跨平台和高性能渲染，Vulkan 是必经之路。但工作量巨大——Hazel-dev 的 Vulkan 代码有上万行。

更现实的方案：先完善 OpenGL 后端，确保架构可以切换后端（通过 `RendererAPI` 抽象层）。

#### 7.3 物理引擎集成

用 Box2D / PhysX 替代自定义 SPH 辅助函数。SPH 流体可以作为独立功能保留。

#### 7.4 动画系统

如果需要角色动画，需要完整的 Animation System：
- Skeleton
- Animation Clip
- Animation Graph / State Machine
- Blending
